## Mental model

**One process. One port. One launchd job.** That's the whole adapter.

It does five things from `127.0.0.1:47832`:

1. **HID observer** — opens the XP-Pen vendor page exclusively (`kIOHIDOptionsTypeSeizeDevice`), decodes button + wheel + battery reports.
2. **Layer state machine** — K2 advances 1→2→3→4→1; broadcast as `layer_change` events; LLMs read/write via `get_current_layer` / `set_current_layer`.
3. **Wheel state + binding** — CW/CCW ticks update a signed counter, broadcast as `wheel_state`. Optional binding lets ticks fire keystrokes / AppleScript / shell commands. Set/cleared via `set_wheel_binding`.
4. **Keystroke + shell + AppleScript synthesis** — direct `osascript` calls for keystrokes, `spawn` for shell commands. K1/K7/K8/K11 are hardwired across all layers; K3-K6, K9-K10 dispatch per-layer keystrokes from `xppen-mappings.json`.
5. **HUD HTTP server + MCP-AQL endpoint + control endpoints + recordings-folder watcher** — all on the same port, all in the same process.

Reference philosophy memory: `MCP-AQL adapters are capable layers, not dumb dongles`. Pushing state, interpretation, and semantic ops into the adapter is the design intent — not scope creep.

## Voice loop (how K11 reconfigures the keypad)

```
[K11 press]
  ↓ adapter dispatch hits HARDWIRED_ACTIONS.K11
  ↓ which spawns: tools/k11-voice-trigger.sh
       │ saves current SuperWhisper mode → /tmp/sr-prev-mode
       │ open superwhisper://mode?key=custom
       │ open superwhisper://record
       │ touch /tmp/sr-voice-recording (lock)
       ↓
[user speaks "set the wheel to control brightness"]
       ↓
[K11 again]
  ↓ helper sees lock, sends Opt+Cmd+3 (toggleRecording) to stop
       ↓
[SuperWhisper auto-stops on silence OR was just stopped]
  ↓ transcribes → writes ~/Documents/superwhisper/recordings/<ts>/meta.json
       ↓
[adapter's `sw-watch` fs.watch fires]
  ↓ polls meta.json for ≤30s until rawResult is populated (SW writes the
    file empty first, fills in transcript later)
  ↓ filters on modeName === "Shortcut Remote command"
  ↓ triggerVoiceCommand(text, "sw-recordings-watch")
       │ broadcasts voice_command_received
       │ spawns: claude -p "<system prompt + transcript>" --allowedTools "..."
       │ removes /tmp/sr-voice-recording lock
       │ restores SuperWhisper to /tmp/sr-prev-mode
       ↓
[claude -p reads ~/.claude.json → connects to this same adapter via MCP]
  ↓ uses mcpaql_update / set_wheel_binding (or whatever fits)
  ↓ posts an annotation summarising what it did
       ↓
[wheel binding changes, HUD updates live, user keeps working in their app]
```

Key files:

- `tools/k11-voice-trigger.sh` — start/stop toggle helper
- `adapter/src/server.js` — `startSuperWhisperWatcher()`, `processSuperWhisperMeta()`, `triggerVoiceCommand()`, `VOICE_SYSTEM_PROMPT`
- `~/Documents/superwhisper/modes/custom.json` — the SuperWhisper "Shortcut Remote command" mode (we no longer rely on its `script` field; SuperWhisper 2.13 dropped it from the UI)

## Landmines (you will hit some of these — pre-loaded answers)

### SuperWhisper 2.13 dropped per-mode scripts from the UI

The `script` and `scriptEnabled` fields still exist in the JSON but the UI doesn't surface them, and the binary's `AppleScriptManager` is internal-only. The current architecture **does not depend on SuperWhisper's script field**. We watch `~/Documents/superwhisper/recordings/` ourselves. If you find yourself trying to inject scripts into mode JSONs again, stop — SuperWhisper will overwrite them.

### SuperWhisper rewrites mode JSON

When SuperWhisper reloads (restart, mode-list refresh, app update), it rewrites mode JSON from its in-memory state. Direct edits to `type`, `languageModelEnabled`, etc. don't stick across SW restarts. Rely on the recordings-folder watcher; treat the mode JSON as read-mostly.

### `meta.json` is written empty first, populated later

The fs watcher fires on the file appearing, but `rawResult` is empty for the first few seconds. `processSuperWhisperMeta()` retries every 1s for up to 30s before giving up. Don't simplify this away.

### `claude -p` argv ordering matters

`--allowedTools` is variadic — if it follows the prompt, it eats the prompt as tool names. Always pass `claude -p <PROMPT> --allowedTools <LIST>` in that order. (See the spawn in `triggerVoiceCommand`.)

### `claude -p` won't call MCP tools without `--allowedTools` (or `--permission-mode`)

Without an explicit allowlist, claude responds with text only and never calls the tool. We use `--allowedTools "mcp__shortcut-remote__mcpaql_read mcp__shortcut-remote__mcpaql_update"` — explicitly scoped to our MCP server. **Do NOT use `--permission-mode bypassPermissions`** — Mick said no on 2026-05-02. Stay with allowlists, let hooks do the rest.

### Brightness via AppleScript `key code 144/145` is a no-op on modern macOS

It returns success but does nothing. Use `betterdisplaycli` instead (now installed; integration enabled). See `2026-05-03-next-brightness-via-betterdisplay.md` for the brightness binding plan.

### F-keys above F15 for any global hotkey we claim

F16-F20 (mac codes 106/64/79/80/90) are unused by macOS and apps. Default to F18 (79) when picking a new global hotkey. Don't grab digits/letters with modifiers — they collide with app shortcuts. Stored in memory: `hotkey_convention_f_keys_above_f15.md`.

### Wheel binding action shapes (validated by `set_wheel_binding`)

Each side (cw / ccw) must be one of:

```js
{ mac_code: number, modifiers?: string[], label?: string }   // keystroke (osascript)
{ applescript: string, label?: string }                      // raw AppleScript
{ command: string, args?: string[], label?: string }         // shell exec via spawn
```

`modifiers` defaults to `[]` if missing — synthesizeKey was hardened on 2026-05-02 after an LLM-issued binding without modifiers crashed the daemon (the HID event handler propagated the throw). Defense-in-depth: `performAction` is wrapped in try/catch, and there's a process-level `uncaughtException` net.

### "Stop and disable" requires manual re-enable from terminal

The HUD's "⚠ Stop & disable" button runs `launchctl disable + bootout`. To re-enable, run:

```bash
launchctl enable gui/$UID/org.mcpaql.shortcut-remote && \
launchctl bootstrap gui/$UID ~/Library/LaunchAgents/org.mcpaql.shortcut-remote.plist
```

The HUD shows this command in the response when you click Disable. Document for the user.

### afplay overlap on rapid wheel ticks

`do shell script "killall afplay 2>/dev/null; afplay tink &"` cuts the previous tick when a new one starts. Don't drop the killall — fast spinning queues otherwise.

### Lock files for K11 toggle

K11's start/stop toggle uses `/tmp/sr-voice-recording` (recording lock) and `/tmp/sr-prev-mode` (saved SW mode). Both auto-cleared by the recordings watcher when transcript arrives. 60s TTL on the recording lock for stale-cleanup. If the watcher fails to restore the mode, blow them away by hand: `rm -f /tmp/sr-voice-recording /tmp/sr-prev-mode`.

### Keypad has K1, K2, K7, K8, K11 hardwired across layers

| Key | Hardwired action |
|---|---|
| K1 | Open / focus HUD (`open_hud` action shape, falls back to `open URL` if no HUD tab) |
| K2 | Advance layer (1→2→3→4→1) |
| K7 | SuperWhisper default mode (Opt+Cmd+3) — user's normal dictation |
| K8 | Escape |
| K11 | Voice command — switches SW to "Shortcut Remote command" mode and starts recording |

K3, K4, K5, K6, K9, K10 are per-layer. K11 + wheel together are the AI input surface (no synthesis on wheel by default; binding is what flips that).
